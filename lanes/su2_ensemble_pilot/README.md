# Measured 2+1D SU(2) Wilson pilot

This lane adds a runnable small-lattice sampler and supplies **actual sampled
gauge-field measurements** to the spectrum workflow. The stored data are not
constructed spectral curves. They are exploratory finite-volume Monte Carlo
data, with no accepted glueball mass or established equilibration/mixing claim.

This change depends on the ensemble preparation tools in PR #4. Its PR is based
on that branch; merge the preparation work before this addition. The sampler
itself uses NumPy; preparation and fitting use the spectrum lane's NumPy/SciPy
requirements. No API keys, GPU, paid services or downloaded gauge ensemble are
needed for the fixed-budget pilot.

## Model and algorithm

The lattice has periodic shape [Euclidean time,x,y]. Store one SU(2) unit
quaternion on each positive link. The action convention is exactly

    probability proportional to exp[beta sum_p Tr(U_p)/2].

A single-link proposal left-multiplies the old link by either a Haar-distributed
SU(2) element (probability 0.1 in the stored pilot), or a fixed-angle rotation
about a uniformly sampled axis. Both proposal distributions are invariant under
inversion. Accept with min(1,exp[beta*(new-old plaquette-trace sum)]). Each link
update therefore obeys detailed balance with the Wilson measure. A sequential
sweep is a composition of invariant updates; the sweep as a whole is not claimed
to be reversible. The Haar mixture supplies proposals across the full group.
All calculations are ordinary finite-precision numerical simulation.

For clarity, the implementation evaluates all four incident plaquettes before
and after a proposal. It does not depend on an optimized staple formula sharing
the measurement code. Tests independently rebuild the action using complex 2x2
matrices and coordinate neighbours, compare local changes to the full action,
check quaternion/matrix products, and verify gauge invariance of the action and
measured observable. At beta=0 every proposal is accepted. These structural
checks do not establish convergence of any finite run.

Only the spatial plaquette operator is measured initially:

    Q(t) = sum_(x,y) [1-Tr(U_xy(t,x,y))/2] / sqrt(spatial_volume).

Each saved field supplies Q on every time slice. Vacuum subtraction is done by
the ensemble converter, including each bootstrap replica's own mean. Periodic
translation averaging, covariance and fit conventions remain those of the
[preparation workflow](../glueball_spectrum_analysis/ENSEMBLES.md).

## Reproduce the measured pilot

```sh
python -m pip install -r lanes/glueball_spectrum_analysis/requirements.txt
python lanes/su2_ensemble_pilot/tools/run_pipeline.py --output-dir /tmp/su2-pilot
```

The driver runs beta=2 at shapes 8x3x3 and 8x4x4. For each volume there are two
independent random streams, seed 101 with a hot start and seed 202 with a cold
start. Each chain omits 128 initial sweeps, saves 64 configurations four sweeps
apart, and uses a fixed proposal angle of 0.6 radians plus the Haar mixture.
Thus each volume has 128 saved configurations. The run is explicitly bounded:
165,888 link-update attempts for L=3 and 294,912 for L=4.

For each volume the driver tries block lengths 4 and 8, 48 bootstrap replicas
with seed 902, and inclusive windows 1:3 and 1:4. The initial 128 sweeps are
already omitted by the sampler; the preparation discard is explicitly zero.
The common time extent is 8, so the converter retains lags 0 through 4.
A finite-periodic-time cosh fit assumes vacuum dominance; this pilot does not
independently establish that assumption.

A single configurable sampling run can also be made with `tools/sample.py`:

```sh
python lanes/su2_ensemble_pilot/tools/sample.py --output /tmp/operator-samples.json \
  --beta 2 --spatial-extent 3 --time-extent 8 \
  --seed 101 --start hot --seed 202 --start cold \
  --warmup 128 --samples 64 --sweeps-between 4
```

The command validates its controls and enforces a default limit of two million
link-update attempts before starting. The explicit `--max-updates` option can
change that research budget. Fixed seeds replay on the same implementation and
numerical platform; bitwise agreement across different libraries/platforms is
not guaranteed.

## Actual outcome: insufficient correlator signal

The checked-in `examples/` retain both raw operator sample files, all four
analysis reports, CSV tables, and `pilot_summary.json`. Intermediate correlator
files can be regenerated by the driver. Source code hashes, sample-byte hashes,
configuration IDs, chain starts, block draws, software versions and final-field
hashes provide provenance. The raw final links are not stored in these files;
their hashes can be checked by rerunning the fixed recipe.

| Spatial extent | Measurement acceptance, hot/cold | Normalized projected C(1)/C(0) | Later times |
|---|---|---|---|
| 3 | approximately 0.536 / 0.534 | approximately 0.0432 | C(2), C(3), C(4) negative |
| 4 | approximately 0.532 / 0.535 | approximately 0.0434 | C(2), C(3), C(4) negative |

Both requested windows are rejected at both block lengths and both volumes
because the current fitter requires at least three finite positive projected
correlators. All reports have `NO_USABLE_FITS` and no selected plateau. Finite
sample estimates may be negative even when the underlying transfer correlator
is nonnegative; these observations do not demonstrate negative physical spectral
weight. Changing block length changes uncertainty estimates, not the central
connected correlator. The small variations in printed central values reflect
floating summation order.

Hot/cold starts and split-chain plaquette means are recorded, but no convergence
test is passed or inferred from their appearance. The block monitors remain
descriptive. These data establish that sampled gauge fields can enter the full
workflow and that inadequate signal is reported explicitly. They provide no
mass comparison, finite-volume correction or continuum extrapolation.

Next numerical work should improve overlap with low-energy states (for example,
a separately validated spatial smearing/operator basis), increase statistics
under a stated budget, and then assess dependence, time extent and volume.
The fixed-budget pilot is retained as an outcome, without selecting a more
favourable seed, reducing fit requirements or manufacturing a mass estimate.

## Validation and sources

```sh
python -m unittest discover -s lanes/su2_ensemble_pilot/tests -v
```

Six regression tests cover matrix-oracle action differences, quaternion algebra,
gauge invariance, beta-zero acceptance, seed replay, preparation compatibility,
control validation and the update budget. This is a numerical comparison lane;
it creates no proof gate and supplies no analytic proof dependency.

- Metropolis et al., *Equation of State Calculations by Fast Computing Machines*
  (1953), https://doi.org/10.1063/1.1699114: acceptance-method origin.
- Creutz, *Monte Carlo study of quantized SU(2) gauge theory* (1980),
  https://doi.org/10.1103/PhysRevD.21.2308: SU(2) Wilson simulation context.
- Athenodorou and Teper, *SU(N) gauge theories in 2+1 dimensions: glueball spectra
  and k-string tensions*, https://arxiv.org/abs/1609.03873: spectral practice and
  comparison targets. Its published mass results are not independently reproduced
  by this small pilot, and it does not validate our sampler implementation.
